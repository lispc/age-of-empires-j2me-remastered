# aoe/ai — 玩家 AI

规则式玩家 AI 包。接口 `PlayerAi.tick(c game)` 每帧首在 paint/Timer 线程被调
（c.java 帧首 hook，`-Daoe.playerAi=<全限定类名>` 反射装载；装载失败/tick 异常
打 `[ai]` 日志并禁用，不影响游戏）。hook 在 onPaint 帧首，**不受 screenState
门控**——弹窗态（ss==2）下模拟停走但 AI 照样被调，AI 须自按 -7 关窗。

## RuleBasedAi

随机图（gameMode=0）Easy/Medium/Expert 通用。成绩（2026-09-03 第四批 v35 定型
= v30 + Expert 波 1 接战微操四件套）：Medium 三区间 n=10 合计 **26/29 决胜
（89.7%，与 v30 一致）**——1000+ 9胜1僵持（1004 退化图）/ 1010+ 9胜1负 /
2000+ 8胜2负；Easy n=5 4胜1僵持；**Expert 1000+ 3/10 + 复测 1/10（合并
4/20=20%，与 v30 的 22-33% 同噪声带，未达 ≥50% 目标）**。

第四批（波 1 接战微操）结论：微操的交换比收益是实的（[combat] 统计 2.46→
3.0-3.5，我方死亡率 -23%，崩盘推迟 ~50%），但决胜胜率不动——约束不在交战
质量而在围城经济/产能总量（敌 8× 采集+电平触发补员+免费资源滴）。胜局全是
OVERWHELM（m55 威慑压发波→攒 12-17 兵平推）。机制新考证（索敌=槽序第一个
非最近、攻击按格结算离格清零装填、受击反扑改写 slot[2]、群令清攻击计数器、
塔每 17t 一发）见 `docs/research/rulebased-ai-medium-iteration.md`「波 1 接战
微操（第四批）」。第三批（波次建模）结论：预测器已落地验证（发波跨越点误差
≈0），但架在其上的五个行为变体（v25-v29 抢攻/村民参战）全部 ≤ 基线并回滚。

战略一句话：**塔防吸收敌方 all-in → 集结后反击拆敌 TC**（拆 TC 即胜）。拼经济
必输（敌 3.07×/8× 采集 vs 我方 4 村民硬上限 + pop 25），塔不占人口且完工计入
hdr[55] 军值（威慑敌 all-in 判定），是唯一的免费战力。

每 8 tick 决策一次，模块顺序：

1. **态势扫描**：双方单位/建筑全量读。我方村民按 action/目标格归工种（木/金/石），
   军事计数量与价值（Σ(攻+甲)）；敌方塔（完工 type≥12）按 hdr[45]+hdr[46] 折算
   进"防御军值"（总攻门槛用，v4 起——不算是送死）。**波次预测器**（v24 起，
   只读+打点不改行为）：hdr[1][55] 滑窗最小二乘拟合斜率 → 外推跨越
   need=max(aiAttackThreshold, 4×hdr[0][55]/5+1) 的时刻 + 行军估值 = 下一波到家
   eta；敌军事单位 slot[2] 目标落我 TC 4 格内 ≥4 个 = 发波侦测（WAVE 日志）。
2. **弹窗自关**：ss==2 时 `onKeyPress(-7)` 后返回（z=62/z=70 信息弹窗冻结世界，
   headless 无人关窗 = 永久 STALL，seed 1010 实测冻 27 万 tick）。
3. **军事**：
   - 敌兵进我方 TC 10 格（DEFEND_D2=100）→ 近战群令压上；弓兵/投石机停在
     入侵者朝防御锚点 3 格处开火（远程不送近战圈）；敌 t8 在 20 格内时远程优先点杀
     （投石机远程拆塔，近战无解——agent-operations §5.1/r29）。
     **塔援护（仅 Expert）**：敌兵贴近任一完工塔 6 格内同样触发 DEFEND——
     Expert ×8 波次会逐个拔掉外圈孤塔（v15 复盘：5 塔被白拆 4 座军队在旁观）；
     Medium 上同机制反而把军队拉离 TC 塔圈吃败仗（v16 实测 6/10），故按
     `aiGatherMultiplier >= 1024` 难度门控。
     **Expert 波 1 接战微操（v35 四件套，全在 expert 门内）**：① 环形拦截——
     近战钉在锚点朝敌 3 格塔火重叠区等接敌，不冲入侵者（冲锋=出圈被围殴）；
     ② 集火闪避——被敌攻击态锁定（敌 slot[5]==我格）的单位每决策横移一格
     （攻击按格结算，离格=敌装填清零重追），落点塔圈内优先，人数上限
     milCount/2；③ 投石机猎手——敌 t8 贴近塔/TC 10 格派 ≤2 快腿近战直取
     （塔对射射不过 t8），每决策重投；④ DEFEND 逐单位下令——攻击态/回血中/
     猎手单位不被 48t 群令重发打断装填。遥测：摘要行 `dodges=/hunts=`。
   - 残血（HP<100）回撤 TC 背敌侧站桩回血（0.5 HP/tick），HP>220 归队——
     消耗战里保老兵 = 省替换金，对 3.07× 产量的敌人是刚需（v11 关键胜率来源）。
   - 反击触发（需家门清净）：敌主力被歼（峰值 ≥5 且现存量 ≤1/3）/ 碾压
     （军值 ≥130 且 ≥ 敌防御军值 4/3）/ 僵持兜底（t25000 后）/ **贴脸图闪击**
     （双方 TC ≤14 格：消耗战必输，兵力不劣直接上）。**Expert 反击门槛抬高**：
     ≥10 兵且军值 ≥ 敌塔计入后的防御军值（7 兵反击=把家底送进敌塔环）。
     进攻中小股（≤3）反扑不撤，大股撤；1500 tick 无进展判定停滞撤回重整。
   - **进攻两阶段（v14）**：先全军集结到敌 TC 朝我 7 格（警戒圈 6 格外沿，
     顺带触发敌防御模式反扑空巢），到齐 2/3 或超时 700 tick 再一起扑敌 TC——
     兵种移速差 4 倍（投石机 256 vs 剑士 1024），群令直发=添油送死
     （v13 败局 2001/2006 复盘实锤）。
   - 互瞪僵局诱敌：t15000 后久无接触且敌蹲家 ≥10 兵 → 派最便宜的兵直扑敌 TC
     触发其防御模式反扑，喂给我方塔阵（§5.3 调虎离山；驻防群令会召回诱饵，
     靠每决策重投续上）。
4. **村民**：闲置（action=0 且已到目标格；采集→交存→返矿全自动，§10 定论）
   与卡死（行军 300 tick 未动 → 目标拉黑 3000 tick）重派；配额 boot 期 2木1金，
   封建后 1木2金（塔 <5 座时压 1 人采石），开战后（敌亮过 6+ 兵）1木3金。
   在岗配额漂移由"每次决策最多换 1 人"的主动再平衡修正（含 v15 石断供补救：
   需石而石工为 0 时放宽抽调门槛）。敌兵贴脸 7 格 → 村民撤到 TC 另一侧。
   资源点用自扫 findResource（引擎 findNearbyResource 缓存双方共享，会把敌村民
   引到我方资源点互殴）；**findResource 有战区概念（v14）：距敌 TC <10 格的
   资源格不派工、不建营地**（无候选才回退不过滤）——v13 seed 2004 复盘：
   最近金矿在敌 TC 3 格处，矿工逃命/重派死循环金收入归零，矿场原地被拆 6 次。
   **纪律：村民配额/再平衡全是 +1 缓冲的阻尼收敛，不许做"严格收敛/急救抽调"——
   会与逃命链互激成震荡环（v18/v19/v22 三连败实锤，v18 单局 36 次 rebalance）。**
5. **科技**：封建（兵营前置）→ Forging / Watch Tower / Gold Mining /
   Double-Bit Axe / Scale Mail（金 ≥25 才研）/ Stone Mining（塔未满 5 座时）；
   城堡时代（磨坊+铁匠 ≥2 且资源富余）→ Iron Casting / Chain Mail / Guard Tower。
   科技必须尽早就位——GoldMining/WatchTower 直接决定首波窗口的金收入与塔生存
   （v5 推迟到 8k 的实验证明是灾难）。
6. **建筑**（一次一座，放下自动成型 ~32 tick）：房屋1 → 伐木场 → 兵营 →
   走廊塔1 → 采矿场 → 走廊塔2 → 铁匠铺 → 射箭场 → 走廊塔3-5 → 房屋2-4 →
   磨坊 → 马厩 → 攻城工坊。塔位 = 我方 TC → 敌 TC 走廊上 4/6/9/12/16 格阶梯
   （r26 验证的最优汇率防术；近距图钳到走廊 60% 内，别蹭进敌警戒圈）。
   **交战中（敌兵 12 格内）只补塔**（门槛 22木/6金/16石，塔被拆第一时间原地补）。
   **Expert 专链**：紧凑塔环 3/5/7/9/11 格（外圈孤塔援护不及=白送）→ 塔 2 后
   立刻补满 4 房（pop=兵力，卡 pop 时金囤 100+ 用不掉）→ 第二兵营 → 塔 3-5 →
   铁匠铺 → 射箭场。注意 `queueUnitTraining` 只排同类型**第一座**建筑
   （c.java:6519 记录序扫描），第二兵营靠直写队列位（rec[+2]+=65536 +
   hdr[49]++ + hdr[66+t]++，语义=排队不付款、产出时才扣）。
7. **生产**：兵营（剑士/民兵）/射箭场（弓兵）各维持 ≤2 在训，铁匠铺 ≤1 台
   投石机（金 ≥40 才排；**t8 产自铁匠铺不是攻城工坊**——queueUnitTraining
   case 8 → 建筑 6），马厩 ≤2（封建侦察/城堡骑兵自动换形），攻城工坊 ≤1 冲车
   （金 ≥60）。产兵扣款在产出时，排多不亏但占人口名额。

确定性：只按 tickCount 节流，无墙钟、无随机数（也不许碰游戏 nextRandomInt）。

## 怎么跑

```bash
# 批量胜率（10 局 Medium，种子 1000 起，-b 开 BFS 寻路，-k 留每局日志）
tools/ailoop.sh -n 10 -d 2 -a aoe.ai.RuleBasedAi -s 1000 -t 240 -k -b
# Easy 复测
tools/ailoop.sh -n 5 -d 1 -a aoe.ai.RuleBasedAi -s 1000 -t 180 -k -b
# 窗口观战
./run.sh    # 或任意方式启动后加 -Daoe.playerAi=aoe.ai.RuleBasedAi（-Daoe.tickms=40 加速）
```

日志：`[ai]` 前缀（assign/rebalance/build/research/DEFEND/ATTACK（带触发原因
CRUSHED/OVERWHELM/DESPERATE/CLOSERUSH）/RETREAT/ABORTED/STALLED/BAIT/STUCK +
每 500 tick 态势摘要含敌峰值与塔数）；诊断配合 FIFO `aistate`（`tools/aoectl aistate`）。

## 已知边界

- seed 1004 型退化图（无可达金矿 + 敌 TC 被塔围死）：僵持，可接受（三难度同图同症）。
- 高方差近距 rush 种子：Medium 2000+ 区间仍有个位败场（最终复测 2004/2008）——
  敌 3.5-6k 到家时金收入上限是硬约束。
- Expert（×8 采集 + 每 tick 出兵 + 免费资源滴=敌村民数/1000t）：决胜 20-33% 是
  规则式路线的当前上沿——败局样态为 4-5k 起敌首发波+持续梯队碾过产能上限
  （2 兵营×1/256t）。第三批证伪"时机套利"（预测器够准但抢攻/全民皆兵全输），
  第四批证伪"微操决胜"（交换比 2.46→3.0+ 但胜率不动；塔环加长卡死建筑链、
  远程站位调整无效）。再上 = 结构性问题：围城经济/跨波次资源规划。
- 同一种子跨跑结果会翻（菜单导航墙钟相位）：只信批量胜率。
