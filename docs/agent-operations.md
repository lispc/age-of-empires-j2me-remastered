## 1. 会话启动协议

### 1.1 启动命令块（r13–r18 各轮一致）

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17
cd /Users/zhangzhuo/repos/personal/age-of-empires-j2me-remastered
./gradlew compileJava -q                      # 源码有改动时先编译（r16/r17 惯例）
mkdir -p /tmp/aoe-playN/saves                 # 每轮独立目录 + 存档目录
rm -f /tmp/aoe-playN/fifo && mkfifo /tmp/aoe-playN/fifo
java -Daoe.headless=1 -Daoe.dev=random:1 -Daoe.tickms=40 -Daoe.debug=1 \
  -Daoe.saveDir=/tmp/aoe-playN/saves -Daoe.devMouse=/tmp/aoe-playN/fifo \
  -cp build/classes/java/main:build/resources/main aoe.Main \
  > /tmp/aoe-playN/session.log 2>&1 &
```

- `-Daoe.dev=random:1`：守护线程走真实菜单流直进随机图任务。
- `-Daoe.tickms=40`：25 tick/s；日志里的 `ar=` 单位就是 tick（ar≈34.6k ≈ 现实 23 分钟）。
  ⚠️ 手册中一切"游戏内速率"数值（攻速/回血 6.25HP/s/行军速度/训练 256 tick 等）若按
  旧 tickms=80 记录，在 40ms 下全部 2 倍速——引用速率先对照本节换算（r21 勘注）。
- 存档目录一律 /tmp，防覆盖用户档（DEVELOPMENT.md 纪律）。

### 1.2 进任务确认

```bash
sleep 8..12 && grep -n "in mission" /tmp/aoe-playN/session.log   # 出现即已进任务
echo "state" > /tmp/aoe-playN/fifo; sleep 1.2
tail -45 /tmp/aoe-playN/session.log | grep -v '^\[dbg\]'          # 或直接读 fifo.json
```

- 首个 `state` 应返回：光标/cam/单位表（开局基线见 §4.1）。开局会自动写 checkpoint
  `saves/auto.aoesave`，立刻 `python3 parse.py saves/auto.aoesave` 建资源图（r18 标准开局动作）。
- `grep -c "ar=" session.log` 可看 tick 是否在走；`tail` 看有无 Exception/watchdog。

### 1.3 节奏纪律（最重要的一条）

- **每条 FIFO 命令间隔 ≥0.3s**。r17 实测 <40ms 的批量写会合并丢包（12 连发只中 1 条）；
  r18 用 `q.sh`（0.3s/条）全程无丢包。triage r17 补充：部分"丢包"实为菜单/弹窗态静默
  忽略输入，不是传输丢包——两种情况都用"放慢 + state 回读"排查。
- 参考实现（复制到本轮目录）：`/tmp/aoe-play18/q.sh`——`./q.sh "ctile 20 62" "key -4" ...`。
- 也可以用 FIFO `script <文件>`（支持 `sleep 毫秒`，见 DEVELOPMENT.md）。

### 1.4 接力协议（r21 起：永不重开一整局）

20 轮教训：每轮从零开局的"重复劳动"占时过半。接力制三原则：

- **checkpoint 命名**（save 到本轮 saves/）：`boot`（开局稳定点：首批建筑完工）、
  `feudal`（升封建完成）、`army12`（总攻兵力到位）、`attack1`（总攻发起前）。
  关键节点必存，失败回滚到最近 checkpoint 换战术重试，**同一局内多试几种打法**。
- **跨轮接力**：agent 到 60-90 分钟或上下文过半即止损交棒——save 最新进度 + BUGS.md
  写清"当前局面/下一步"，下一轮 agent 直接 load 续玩。跨局接续同理（Defeated 后
  进程存活，`-5` 关简报即新局，r20 实测）。
- **接手第一步**：`state`/`sitrep` 摸清局面 → `ls saves` 找最新 checkpoint → 读
  BUGS.md 尾部"下一步"→ 继续。禁止无脑重开。
- **load 有任务代次门控（r21）**：跨任务 load 会被 mission mismatch 拒载
  （save 的关卡代次 ac/aF 与当前局不符时报错/静默不载）——跨代次接续只能靠
  "先滚到同代次任务再 load"，同任务内的 checkpoint 不受影响。load 后必须 state
  验证局面与预期一致（单位/资源），**不信 load 回显**。

## 2. 坐标系统（最易错，先读这节再动手）

### 2.1 物理帧缓冲 vs 逻辑空间

- **FIFO 的鼠标坐标（move/click/rclick/drag 的 x,y）是物理帧缓冲空间** = 逻辑 240x320 ×
  SCALE 2 = 480x640（DEVELOPMENT.md；triage r14 钉死）。`dump` 出的 png 同为物理 2x。
- `ctile <tx> <ty>` 内部用实时相机换算物理像素，**不用自己算坐标，首选**（DEVELOPMENT.md；
  triage r8 入库）。
- 手工算像素（给 click/move 用）的公式（物理基准，triage r14 修正、r17 受控实验复核、
  r18 复验）：
  ```
  sx = 32*(tx-ty) - 2*camX - 64        # 菱形中心；上角是 +3（会被北邻格截胡，r14）
  sy = 16*(tx+ty) - 2*camY + 19
  camX/camY 从 state 的 fifo.json "cam" 字段读。
  ```
  历史：r13 及更早的逻辑公式 `(16*(tx-ty)-camX+28, 8*(tx+ty)-camY+76)` 已废弃；
  r17 曾报"只有左上 1/4 可点（逻辑/物理混用 bug）"，triage r17 受控实验裁决为
  **用错常数，现公式正确**，该结论作废。

### 2.2 屏内窗口与相机缓动

- ctile 的落点必须落在屏内，否则**静默无 pick**（px 416、负 px 均实测丢失，r18）；等价
  说法：目标格须在当前视野内（r15 实测屏内盒约 Δdiff∈[-3,2]、Δsum∈[-12,5]）。远距目标
  先跳相机（§2.5）再点。
- **相机是缓动的**：光标键/选中单位后 cam 慢半拍，用 stale cam 算像素会偏 1–5 格
  （r18 三次复现；r12；r14"点击前 <2s 内取 cam"）。菜谱：方向键走完 → `state` 重读
  cam → 再 ctile。
- 相机被选中单位/训练完成事件拖着走（§3.6），所以**每次操作前都重查 state**，这是硬纪律。

### 2.3 probe 校准法与漂移

- `probe x y`（屏幕物理像素）→ `[pick]` 行返回 tile 线性索引，是像素→tile 的标定手段
  （r14 用 5 点校准反解公式）。probe 随镜头缓动漂移，每步重新 probe（triage r6）。
- probe 的局限（triage r8 降级）：返回的是渲染 tile id，**不可判地形/可走性**；界外/水
  返回 -2 或伪 id。r17 干脆判定 probe 不可靠、以 state 的 Q（cursorTileIdx）为准。
- 闭环校准法（r14）：ctile → state 读 cursor → 与期望差几格就补偿重发，2–3 次收敛。

### 2.4 方向键与 mod4 卡位

- 映射：`-1`=NW(-1,-1)、`-2`=SE(+1,+1)、`-3`=SW(-1,+1)、`-4`=NE(+1,-1)，每按 1 格
  （r13/r15/r17 一致）。相机跟随光标（约每格 32x/16y 物理像素，r17）。
- **光标格不变量是 (x+y) mod 4，且任务内"类"锁死**（r24 升格）：方向键 ±2、全图
  跳转 ±4 都不改变 sum%4——**boot 时光标在 TC 上=升封建的唯一窗口**（开局第一步
  就该做），任何漂移后数学不可达，只能 ctile/click 救（triage r11，修正 r10 的
  "奇偶二色"说法）。
- 方向键不依赖拾取，光标在雾格/虚空上也能走（r15）；例外：光标落在水/出界格
  （cursorTileIdx=-1）时方向键被收下但光标不动（r8/r9）——此时唯一出路是全图视图（§2.5）。
- 光标走出可玩边界会被**钳回 [0,63]**（主会话 r17 修复，原版可走出导致指令全废）；
  出界前的贴边路径规划当心 camera 吸附。

### 2.5 '0'（key 48）全图视图 = 远距机动唯一可靠路径

- `key 48` 开/关全图视图（240x120 iso 缩略图 + 白框视野 + 图光标，r13）。
- 菜谱：`key 48` → 方向键移图光标（2 格/步；**图内方向键不受水/雾 guard**，triage r9）
  → 图内 `key -5` = 世界相机+光标联合跳转 → `key 48` 关图回世界（r13/r14/r16）。
  r21 简化菜谱：`key 48` → 方向键到目标 → `key -5`（退出+跳转）→ 再 `key -5`（下令）。
  **光标落虚空（Q=-1）时 key 48 仍可开图、图内箭头仍可走——这是唯一脱虚空出路**
  （r21 救命路径实测）。选择跨图保持。
- **图内 mod4 双不变量同样成立**（r21）：可达目标须 dx≡dy≡0 (mod 2) 且
  (dx±dy)≡0 (mod 4)；箭头数 p=(dy−dx)/4（正=SW，负=NE）、q=(dy+dx)/4（正=SE，
  负=NW）。**负数分支发反方向键**——此处 r21 写错过两次，算完先自检方向。
- **⚠️ agent 高频错误（r21 被用户点名"瞎试"）：忘了这个视图的存在，在屏幕内用
  方向键/ctile 一格格摸索远处目标。任何 >10 格的机动、找敌城、侦察、运兵，
  一律先 key 48 全图跳转。**
- 全图视图内**点击不能跳转**（原版无 world pick，r16）；资源斑点颜色：深绿=林、黄=金、
  灰=石（r15），但斑点像素→tile 校准误差 ±5 格不可信——找资源用 parse.py 读存档（§6.3）。

### 2.6 贴边滚动陷阱

- 逻辑坐标 x≥226 / y≥306 一带是边缘自动滚动区（r15）；裸 `move`/`drag` 终点落在该区会
  触发持续边缘滚动：r14 相机被拖飞、r16 drag 释放点距右缘 90px 导致相机漂 16 格、后续
  点击全废（该楔死 bug 已修：drag 后自动回屏中心，triage r9）。**用 ctile 可完全绕开**
  （DEVELOPMENT.md）。
- 光标进虚空格（海/岛外）后 move/probe 全失效，只能方向键沿岛带走出（r15）。

## 3. 选择与控制

### 3.1 光标 vs 鼠标双系统（triage r12 语义修正，务必分清）

- **tile 光标**（cursorTileX/Y）：只有方向键能移动它；`-5`（confirmAtCursor）只作用于
  光标格。开建筑菜单、放置落位、升时代全走这条路。
- **鼠标像素拾取**（ctile/click/rclick/drag）：不移动光标；选择单位、下移动令走这条路。
- 拾取优先级：单位 > 建筑 > 地面——点资源格/建筑常被自家单位精灵截胡（r13）。

### 3.2 -5 语义表（r10/r12/r13 汇总，r19 源码级补充）

| 状态 | -5 效果 |
|---|---|
| 无选中，光标在己方单位格 | 选中该单位（aE=512） |
| **选中军事/侦察单位（selectedType≥2），光标在己方建筑格** | 开该建筑菜单（`[trace] g->7`，底部信息条+血条）——**村民(type0)永远开不了建筑菜单，只会被当成移动令**（r19 源码钉死：openBuildingMenu 硬门槛 selectedType>=2） |
| **无选中，光标在己方完工生产建筑格** | **排队+1 单位**（§4.4"生产即排队"）——完工建筑（status&0xFF==255）豁免 selectedType 门槛（c.java:4239），-5 连发=连排，无惧 4 秒选中超时（r20 实测） |
| 有选中 | 对光标格下移动令（orderMove，无攻击指令路径） |
| 无选中，光标在空地 | **开暂停/任务菜单（aA=4，坑！）**，见 §7 |

- 建筑菜单门槛源码链（r19）：confirmAtCursor（-5 处理器）要求光标格
  `mapTiles&0x300==256` 且 owner==0 → openBuildingMenu → 硬门槛 selectedType>=2。
- **-7 双用途**（r19）：关弹窗 + **取消幽灵/取消已排队单位（退款）**
  （c.java:4144：selectionMode==1 → clearSelection）。
- **幽灵武装态（selectionMode==1）会吞掉一切 ctile**（去放置分支/静默拒）——
  幽灵=光标格，方向键 -1NW -2SE -3SW -4NE 移动后 -5 落位（r19）。
- 选中建筑 ~100 tick（约 4 秒）后**自动取消选中**（g->7 自动回 g->8，r13）——生产/升级
  要在 4 秒内完成"选中→数字键"闪电连击，或用"选中建筑直接按数字键排队"。
- aE 语义：512=有选中可下令；-1=无选中（此时移动令静默失效，triage r9）。state 头部
  `sel=N` 与单位 `sel=true` 可能不一致（显示瑕疵，低优，r7/r8）。

### 3.3 选单位

- 公式法（r7）：光标格为屏心 (120,160)（逻辑），单位格 (tu,tv) 的屏幕位置
  `x=120+((tu-tv)-(cu-cv))*16, y=160+((tu+tv)-(cu+cv))*8`，click 其物理 2x 坐标即选中。
- 更常用：`ctile <单位格>` 一次命中（拾取单位优先，r13/r14）。
- 失败样态：点完 sel 仍 0/单位 sel=false → 落点被邻格截胡（cam 没稳 / 打在菱形上角），
  等 cam 稳后重发；或该格被己方建筑占先。
- **ctile 的双刃剑（r21 实测）**：ctile 的 release 恒合成一个 `-5`（[void_a] key=-5），
  把**当前选中组**命令到光标格（"幻影令"）——选人时无害（光标=被点格），但相机缓动期
  误拾会把已有选中组拉去错位处（§3.6 缓动 4s 纪律的根因之一）。
- **ctile 选人语义随前置选择态变**（r21）：空选+单击=单选；空选+同格连击=选同 type
  全部；**有选中+单击=替换单选**（先清旧选中）。选中在单位开步后会自清。
- **state 的单位槽位序会重排**（r21：unit 0 从 t3 变 t4）——死亡/压缩后旧索引表
  全部作废，每次 ctile/sel 前 state 现取坐标，勿引用上一次 state 的序号。

### 3.4 同格双击全选同类

- `ctile X Y` 连发两次（各隔 ~0.5s）= 选中全场同 type 单位（selectUnits by type）。
  r16 实测 5 剑士全选；r17 行军菜谱依赖此招。**r20 实测成功率仅 ~30%**：单位持续
  漂移使第二击落空、相机缓动期 pick 管线用旧 cam（像素出负数）——能一次选中就
  立即用，别依赖全选；**fields 验证 selectedType/selectionMark 才是真相，state 的
  sel 标志会说谎**（r20）。
- drag 框选可用（`[band] rect ... selected=N`，triage r2 确认管线正常）但两点限制：
  终点避开贴边滚动区（§2.6）；相机缓动期落点漂移（r14/r16）。
- **选中单位移动后 selection 常自清**（r20）——每跳移动后重选再下令。

### 3.5 移动令链（分段行军）

- 单个单位：选中 → `ctile <空地>` = 移动令（ctile 的 release 合成 -5，triage r16）。
  目标格有单位时 ctile 会变成"选中它"而不是移动（r15）——下令前确认目标格无单位。
- 大部队行军菜谱（r17，实测可用）：双击选同类 → 方向键把光标沿安全走廊走 →
  `rclick <光标自身格的像素>`（始终 <240 逻辑 px，避开拾取半屏问题）→ 全体 orderMove。
  重复推进。
- 长途必须分段：3–5 格一段，段间 state 回读（r15 nav.py order 的用法；r16 用
  "Δsum≤+3 链式 ctile"推进）。
- **全图跳转运兵菜谱（r20 实测，长途最可靠）**：ctile 选中单位（[pick] 验证）→
  `key 48`（'0' 开全图）→ 方向键 NE(-4)/SE(-2) 把光标步进到目标（斜向 2 格/步，
  奇偶约束同 §2）→ `key -5`（=退出全图+光标跳到目标）→ **再按一次 `-5` 下令**。
  **不要多按 key 48**——会重新打开地图吞掉指令（r20 波次脚本翻车根因）。
- 不可达目标（树/矿/水/岩岭/建筑格）行为：沿路径走到断点 → 回退一步 → 停。这不是 bug，
  是寻路失败回退，所有单位通用（triage r11 终裁"order 聋"不存在）。
- rclick 语义：对当前选中单位 orderMove 到拾取格；无有效选中时 rclick = clearSelection。
  注意 rclick 落点曾被相机未稳带偏一行（r17，py-16 补偿）；r13 的 7 次 rclick 全被
  己方精灵截胡成"原地令"。裸 `rclick`（缺参数）曾打崩 FIFO handler（r20 BUG，已修：
  缺参回显 usage 继续服务）。

### 3.6 光标"漂移"三因（r13 定性，操作前必查 state）

1. 相机/光标跟随选中单位；
2. **每次训练/建筑完成，光标+相机自动吸附到完成位置**（最大的漂移源）；
3. 弹窗开启时输入被吃（先 -7 关，见 §7）。

## 4. 生产与经济

### 4.1 开局基线（random:1，出生点跨局可复现；地形/敌城**不可**复现，triage r10）

- p0：2 村民 (22,62)/(20,62) + 1 侦察 t5 (22,61)，TC ≈(21,61)；200 木/100 金/100 石，
  人口 3/5。p1：2 村民 (33,62-63)。
- **任务类型分支（r21）**：存在**纯军事关**（如 mission 2 接续局）——无村民无建筑
  0 资源，初始若干军事单位是全部家底，胜利=全歼敌单位（§9 勘误；本作无爆兵路线，侦察
  定敌建筑坐标后速攻）。开局第一步先 state+存档 parse 判断本局是经济关还是军事关，
  战术完全不同。
- AI 时间线（多轮一致）：ar≈7.4k 已 16 单位（4 民+4 民兵+5 弓+3 侦察）；参数化 raid
  最早 ar≈34.6k 到家（r16）。资源三桶 = **木/金/石，本作无食物**（triage r18 勘误，
  早期"食"全是误读；hdr[4] 是建筑数）。

### 4.2 建造菜单

- 打开：选中村民 → `key 35`（'#'）→ aA=7。**key 35 是 toggle**：再按一次=关菜单

### 4.5 采集循环（经济飞轮，triage r13 证伪"无收入"、triage r18 证伪 r17"全局失效"）

- 菜谱：选中村民 → `ctile <树/矿格>` → 完事。**必须点到资源格本身**（r22 读码
  case768+实测：goto 到邻格=纯移动=闲置；"顺路踩到"资源格会意外触发采集）。
  之后自动循环：采集（slot[+7] 计时，0x66 满载）→ 自动回交存点入账（TC/House 等
  class256 建筑通用，c.java:6234）→ 自动返回采集点（triage r13/r14）。
- 资源类型按格值低 2 位：1=木(hdr5) 2=金(hdr6) 3=石(hdr7)（r14/r18）。
  **判别式统一用 `(v&3)`**（r27 恢复名誉）：parse 系脚本的 lowbyte 分组是**剩余量**
  非种类（实测 189→161 被采中、归 0 消失）——r22"0x7f/0x7e 簇"与 r26"南区金簇"
  的树/金误判皆源于此。雾格 `0x837d/e` 的 0x7d/0x7e 是雾占位符，存档雾格内容
  不可读，只有 (v&3) 可信。m+8"金涓流"翻案：南区 (59-63,62-63) 是 8 格金矿，
  村民在真实采矿；m+9 全程金=0 实证**本作无被动金涓流**。
- 速率实测：1 村民采石 +15/29s ≈31/min；2 村民 ≈36/min（r14）；采金 100→169 约 2 分钟
  （r18）；伐木 +30~40 木/35s/村民（r18）。不同轮数字有出入（资源种类/距离不同），
  **开局务必自测 30–60s 存档差分**（§6.3）。
- 耗尽：树采空后格值归零消失，村民自动 8 邻域找同变体下一格（r14）。
- 已知干扰：村民站在自己标过的格（class512 单位占位标记覆盖地形）会误判"已到达建筑"
  而闲置（triage r14 记录）——看起来卡住就把它重新点上相邻资源格。
- 经济首验纪律（triage r17）：开局 5 分钟内派村民上最近资源格，存档差分看资源涨不涨；
  不涨则本局转纯军事速攻（初始资源+箭塔防御）。

### 5.3 引蛇出洞机制（triage r17 定性 + triage r18 修正）

- 我方军事单位接近敌基 8–10 格 → AI 切防御模式，约 87.5% 兵力直扑我方 TC

  （60/200——aiAttackThreshold 只是高档）；低于全部门槛则**全程纯被动**（mission 2
  敌 armyval 52，八单位驻防但永不主动）。armyval/门槛可从存档 headers 读——开局面
  先读敌 armyval 判断威胁等级，低威胁关可放心经营。
- r18 修正：var_int_i（fields 可读：0=被动/1=防御/2=进攻）可以全程=0，来犯者也可能
  只是近战追击行为——别把"没见 var_int_i 翻转"当"绝对安全"。
- **AI 截击半径 8 格是本作最大团灭圈**（r15 村民#1 之死；**r22 两次 8 秒团灭均在此
  圈**，加粗警告）：村民/落单单位进圈=被弓兵集火点名，行军路线保持距敌城 10 格以上。
- **敌行军独立于 ai 标志**（r24 实测）：质心向己方漂移=raid 已在路上，别等 ai 翻转
  才设防；诱饵要在敌爆到 15+ 单位之前放（mission 开局 ar≈5k 前置侦察敌爆兵速度）。
- **m+12 起敌 all-in 规律化**（r29 实测）：boot 后 10-14k tick、18-26 军、必含
  t7x3+t8x2（m+11 的"冻结 23k"是特例）——boot 工序按 10k 倒计时排布，塔+兵
  在 10k 前就位；敌工人跟 raid 军行动，**敌经济活跃度看工人位置不看余额**。
- **敌出击=接近触发非计时器**（r24 实测）：军事单位距敌 5-8 格即 aggro；触发后

### 5.4 制胜模板（r18 防御反击案 + r20 修订速攻案）

1. 开局：House(15木,人口) + Barracks(20木10石,出兵) 早建；**宏爆兵/`-5` 连发**（§6.1b/§4.4）。
2. **先杀敌 raid 队、保村民**——经济归零=无兵源=崩盘（r20 败因）；村民别离 TC。
3. 军队分驻：主力驻家防反扑，前锋诱敌时家里必须有兵。
4. 总攻 12+ 混编出门；**永不归零：任何时刻留 ≥1 单位**（§5.5）。
5. 接敌选地形（森林咽喉），残血撤退站桩回血；**20 分钟内解决最佳**（r20：107k tick
   拉锯后双线崩盘）。
6. 胜利=**全歼敌单位+清空其生产队列**（r26 补全）：歼敌后拆 TC/Barracks 清队列
   才弹胜利屏；追杀敌重建单位（残存 Barracks 会出 t3）到 0 为止。

**走廊阶梯塔（r26 验证，汇率最优防术）**：塔直接修在敌行军线 tile 上（非家门口），

### 5.5 败北判定

  同理对称（全歼+清生产队列，r26）。
  （triage r18；r16"TC 被拆即败"实为 TC 被拆过程中单位同时归零的案例）。
  留 1 个村民躲家就是保险。
- **r20 首次目击全流程**：最后单位阵亡 → z=98 "You have been defeated" → **自动载入
  下一任务**（新随机地图/新基地，z=74 简报开启；r18 曾见 -7 手动关后进 am=12 失败屏，

### 5.6 敌情情报

- `state`/fifo.json 的 p1 单位表（带 p 阵营、type、tile）就是免费雷达（triage r9 入库）。
- **敌城位置每局不同**，任何坐标情报只对同一局有效，禁止跨局引用（triage r10）。

### 6.1b 战术宏（r21 新增，操作首选——比像素链路快且稳）

服务端直连游戏内部函数的原子命令，绕过拾取/相机/菜单/臂置全部脆弱链。**优先用宏，
ctile/click 菜谱退为后备**。回显在游戏 stdout（`[devMouse] ... OK/FAIL +原因`），
grep session.log 验证；失败是带原因的，不会静默。

- `sel <tx> <ty>`：直选该格单位/建筑（tile 编码直读，不经过像素拾取）。**含替换
  语义**（r22 修复：选新目标前自动清旧选中组——selectUnderCursor 本体不清残留
  sel 位，曾致 goto 连带旧组全军出动撞敌团灭）。**局限（r23）：对"站桩"单位 FAIL**
  （tile 无 0x200 占位标记时不识别）——移动中/站桩单位只能 ctile/drag/光标三路。
  **不分阵营（r28）**：敌我并存格选到敌方单位——sel 前 sitrep 确认我方单位存活。
- **x0q 回显不可信**（r28）：goto all 的 `xNq` 是排队量非接令兵数，x0q 时单位
  可能已接令开步——以 state 位置变化为准。rally 宏是否存在用"直接发一次试"判别。
- **build FAIL 回显=免费探雾器**（r28）：雾格/重复/资源不足三种 FAIL 全带原因，
  新图开荒连发多点位 build 可顺带标定地图。建筑死亡 tile 两态：raw=0x0 或
  0x1604 rubble——判"楼没了"看 class≠0x100。
- `goto <tx> <ty> [all]`：对选中单位下移动令；`all`=扩选全体同类再下令（替代不稳
  的双击全选）。总攻/行军标配。**⚠️ x0q=空集结群**（r24 破案）：ctile+goto 连招必败
  ——ctile 合成 -5 令单位开步→移动清选中→all 扩选空集。**远端集结一律用 rally**；
  回显 `xNq` 的 N=排队量非接令兵数。
- `rally <tx> <ty>`：**全体军事单位集结**（r24 需求）——逐兵种 selectUnits+orderMove，
  互不依赖选中存活，根治 x0q。全军行军/决战集结首选。
- `gather <村民tx> <村民ty> <资源tx> <资源ty>`：直绑采集（r23 需求）——资源格须
  已探明（雾中 FAIL，r30 实测雾检明确回显）；站桩村民 sel 自选失败时先 ctile 选中
  再 gather 即成（r30 一次命中）。**goto 采集绑定是一次性的**
  （r25：到货触发一次→交还后闲置，非树尽）——**可持续采集=自动踢矿工循环**
  （state 筛静态村民→sel 验证→goto 资源格，50s/轮；R25 的 kick-miners.sh 在
  /tmp/aoe-play25/，实测每趟 +3 金）。
- `train <tx> <ty> <n>`：在己方完工生产建筑排队 n 个（aK=0村民 2民兵 3剑士 4弓兵
  5/6骑兵）。**n=数量非兵种，aK 由建筑唯一决定不可选**（r30：House 默认 aK=0、
  Barracks 黑暗 aK=2/封建 aK=3）。排队时宏显式硬检 canAfford+pop（r30+源码 train
  case）——`排队 0/n`=拒，资源不够连僵尸队列都不给；付款仍在出兵时。TC/研究建筑
  报 FAIL(g=2)。**aK=0 产物 fifo 显示 type=1**（r30 实测 4/4：House 产第二种村民，
  t0 疑任务初始赠品）——t0/t1 都是村民（§4.2），选人别只筛 type=0。
- `build <tx> <ty> <type>`：直接放置建筑（付费+施工），绕过 选村民→35→槽→臂置→
  方向键→落位 七步链（臂置间歇失灵/parity 死角全规避）。仍受游戏约束：需有村民、
  canAfford、数量上限（House4/Tower5/Mining2）、格空（占格/雾/出界 FAIL）。
- `tile <tx> <ty>`：一格地形诊断（raw/类目/owner/序号/雾/在建进度）——查建筑是否
  完工、找资源格类型首选。
- `sitrep`：**一行战况**（ar/aA/光标/资源/人口/队列/ai/双方兵力构成/敌军质心）。
  决策前一条 sitrep 替代全量 state 轮询。state 的 fifo.json 也新增
  res/pop/queued/ai 字段（免开存档读资源）。
- **弹窗纪律（宏时代的头号坑）**：建筑首次放置与完工各有教学/完成弹窗（aA=2），
  **弹窗期间 j() 不跑=施工/训练/移动全部冻结**。宏 build 后必须 `-5` 清弹窗再等
  完工（`tools/aoeops.py build` 已封装此流程）。弹窗态 state/sitrep 可用

- 最终报告（BUGS.md 尾部 + 汇报）必须包含一节**「操作经验」**：本轮新发现的操作层技巧/
  坑（命令级菜谱、失效样态、数值），供主会话验证后并入本手册——本手册就是这么攒出来的。
- 最终报告必须包含一节**「反思与给主会话的建议」**：自查本轮效率瓶颈（哪些等待/
  反复试错/找不到信息浪费了时间，附大致耗时占比）、工具缺口（还想要什么宏/指令/
  脚本）、文档缺陷（手册哪里没写清/写错/翻不到）、环境问题（fifo/存档/脚本路径/超时）。
  主会话据此排期改进工具与流程——这是流程滚动的另一半。
- 每条结论标注证据等级：实测（附 log/存档证据）/ 读码（附文件:行号）/ 推测。
- 与前轮结论冲突时，明确写"与 rN 的 X 矛盾"，交主会话裁决，不要自行翻案。
- 战报要素（各轮惯例）：时间线（ar 戳）、双方兵力/资源终值、[combat] 对照、
  存档路径、下轮建议。

### 已结案（证据存档，勿再当悬案引用）

- **采集触发=必须到达资源格本身**（r22 读码 case768+实测收案；r18"停邻格也采"
  系顺路踩到的误判）：邻格纯移动不触发，命令落点即资源格。
- **训练排队占 pop 当量**（r22 复证收案）：t2 占 2 队列当量；pop 10/15+q5 时
  train 0/3 被拒——排 pop 上限按当量算，非单位数。
- **僵尸队列**（r22 实测收案）：木=0 时排队的单位永不出生也不报错（付款在出兵时
  的完整含义），占 pop 当量；首笔资源入账自动解冻——别反复重排，攒到资源即可。
  **r30 勘误限定**：仅键盘 -5 连发路径如此；train 宏排队时显式 canAfford 硬检，
  资源不够直接 `排队 0/n` 拒绝（源码 train case），宏路径无僵尸队列。

- **胜利条件 = 全歼敌单位 + 敌生产队列清空**（r23 首胜；**r26 补全**：全歼后
  不立即触发——拆掉 TC+Barracks 清空敌在训队列后才弹 aA=12；敌 ~10 座建筑可留，
  与"我方 0 单位=败北"近似对称）。r20 简报原文"smash all their buildings"是
  任务描述性文字非判定逻辑。23 轮 0 胜的隐性原因之一就是把"拆光建筑"当成了
  硬性条件。
- **TC 不产村民**（r20 源码：case 9 只有升时代分支）；r17"TC 排村民"误报撤案。
- **House 15木、Barracks(type10) 20木10石**（r21 宏扣款实测）；r16"40木+10金"读错行
  撤案；"Lumber 15木"系列读数同样混入采集干扰作废。
- **type10 官方名 = Barracks**（r21 教学弹窗原文）；升封建前置 a(0,10)>=1=需 Barracks
  ——r15/r16 原判断恢复名誉，r20"需 Lumber 勘误"作废。
- **爆兵三连 -5 = 生产即排队**（r20 源码钉死 §4.4）；"输入时序玄学"撤案。
- **r19"射箭场排剑士"** = 实为 Barracks(type10)（r20 勘误）；射箭场产 t4 弓兵。
- **r19"House=type2/11=磨坊/12=农田"类型表** = r20 真值表作废替换（§4.4）。
- **"载档单位锁死"**（r20 撤案）：后期同批单位全部可动，早期失败全是选中/面板竞态假象。

  被吞的是部分按键输入时序，非查询指令。
