## 脚本字节码格式（权威速查）

脚本 = 块序列 + `127` 结束。块 = 条件 + 动作序列 + `126` 结束。
块首字节 = 条件 opcode；**运行时把首字节翻负 = 块禁用**（动作 op1 启用 / op2 禁用
做符号翻转；文件里初始禁用的块首字节即为负）。块不会自动一次性——条件每 tick
重估，需动作 op2(-1) 自我禁用，否则每 tick 重复触发。
tickMissionScript 每游戏 tick 在世界视图跑一次（screenState 7 也跑），4 个
scriptFrameCounters 每 tick +1。

条件 opcode（参数数 = evalScriptCondition 指针推进，enabled 路径权威）：

| op | 参数 | 语义 |
|---|---|---|
| 1 | neg,玩家,slot,x0,y0,w,h | 该单位**静止**（slot[6]&0xFF00==0，非步进中）且位于 x∈[x0,x0+w) y∈[y0,y0+h)；neg==1 取反 |
| 2 | 计数器c(0..3), v | c ≥ v*10 tick |
| 3 | state | screenState == state |
| 4 | neg,玩家,markHi,type,slot | 选中判定（selectionPlayer/selectedSlot/selectionMark==markHi<<8/selectedType；type=-1 任意）；neg==1 取反 |
| 5 | 玩家,kind,type | 本 tick 事件表（var_int_arr_b，tick 末清零）匹配：kind 0=单位死亡 1=建筑被毁 2=单位训练完成 3=建筑建成（e() 调用处 c.java:7060/7473/6840/7373）；type=-1 任意，0=类型<2，其余精确。**kind 1/3 的类型是建筑号，0/2 是单位号** |
| 6 | idx, val | techFlags[idx] == val（**2 参数**，见下方「格式坑」） |
| 7 | 玩家, idx, cmp, val | playerUnitHeaders[玩家][idx] 与 val 比较：cmp 0:== 1:> 2:< |

动作 opcode：

| op | 参数 | 语义 |
|---|---|---|
| 0 | as, page | 简报弹窗 startMissionBriefing(as, 本关简报res, page) |
| 1 | 块号 | 启用块 #n |
| 2 | 块号(signed) | ≥0 禁用块 #n；<0 禁用本块（一次性触发惯用法） |
| 3 | c | scriptFrameCounters[c] = 0 |
| 4 | 1 字节(被丢弃) | **胜利** briefing(0,98,0) |
| 5 | 1 字节(被丢弃) | **失败** briefing(0,98,1) |
| 6 | 玩家,类型,x,y | 刷兵 a(玩家,类型,x,y,false) |
| 7 | 玩家,sel,x,y | 移动令：sel=-1 全体村民(类型<2)；sel<0 所有类型 -sel 的单位；写 slot[2] 目标格= x<<8\|y。sel≥0 分支两个反编译器都渲染成把**脚本指针**<<3 传给 tickMoveTimer——疑似原版 bug，实测 7 关+3 教学没人用 sel≥0 |
| 8 | 玩家(signed),idx,val(signed) | 写 playerUnitHeaders；玩家=-1 = 双方同写；idx∈5..7（资源）附带 var_boolean_l=true |
| 9 | idx,val | techFlags[idx] = val |

techFlags 相关背景（本任务顺带钉死）：
- 初始值 = res#127（47B）：tf[10]=tf[11]=tf[20]=tf[21]=tf[22]=1，其余 0。
- **tf[10+t] = 玩家建筑类型 t 可建标记**：初始可建伐木场(0)/采矿场(1)；升封建
  (age→1) 置 tf[15..18]（磨坊5/铁匠铺6/射箭场7/马厩8）；升城堡 (age→2) 置
  tf[12..14]（攻城工坊2/城堡3/大学4）（c.java:6030-6048）。玩家建筑被毁时
  onThingDestroyed 也置 tf[10+类型]=1（c.java:7471-7473，=允许重建）。
- tf[23+techId] = 科技 techId 已研究（研究完成统一置位 c.java:6217）；
  tf[36]/[40]/[43] = 塔升级 Watch/Guard/Keep（科技 13/17/20）。

### 格式坑（本任务实测）

1. **cond op6 参数数歧义**：skipScriptBlock 按 3 参数跳（CFR/Vineflower 一致），
   evalScriptCondition 只读 2 个（双证）。res114 按 2 参数解析完美对齐 127、
   按 3 参数错位——权威 = 2。运行时之所以不出事：skipScriptActions 的 switch
   无 default，跳过禁用块时多吃的 1 字节会被当作未知动作逐字节滑过自愈
   （已在 res114 三块上手工模拟验证落点）。**但语义以 enabled 路径为准**。
2. 动作 op4/op5（胜/负）带 1 个参数字节，解释器直接 `++n` 丢弃（疑似原设计
   是延迟/音效号，未启用）。
3. res126 块#18 是 2/3 参数歧义的对照样本：两种吃法都能对齐 127，但 enabled
   路径动作指针由 eval 定 → 2 参数才是真语义（该块动作 = 简报页12，而非
   3 参数误读出的"启用块#12"）。

## spawnMission 布阵格式（res 103..109 / 118..120）

```
[0] RNG种子lo  [1] RNG种子hi   (0,0) → randomMap=true
[2] 玩家起始时代 hdr[0][0]
[3..5] p0 木/金/石   [6..8] p1 木/金/石
[9..10] 光标 tile (x,y)
[11..12] 记录数（小端 u16）
记录（从偏移 13）：
  op1: 类型,玩家,x,y,flags  → 放建筑 a(玩家,类型,x,y,flags,false)
  op2: 类型,玩家,x,y        → 刷单位 a(玩家,类型,x,y,false)
  op3: tile字节,x,y         → 资源格 void_a(tile|0x300, x, y, 31)；种类=tile&3(1木2金3石)，31 趟满载
```

坑：switch 无 case 0/default——**未知 op = 1 字节 no-op**。res104（第1关）尾部
即 1 条 op0 记录 + 4 字节永不被消费的死数据（`01 2f 2e 2d`）。
